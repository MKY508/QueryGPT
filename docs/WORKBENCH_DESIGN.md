# 工作台设计

更新：2026-09-09。本文维护当前交互合同，不累积逐轮修改日志。报表、数据、整理和设置的详细合同分别见 [报告编辑](REPORT_EDITOR_DESIGN.md)、[数据浏览](DATA_VIEW_DESIGN.md)、[数据整理](CLEANING_EDITOR_DESIGN.md)、[设置](SETTINGS_WORKSPACE_DESIGN.md)；模型与执行边界见 [架构](architecture/ARCHITECTURE.md)。

## 主布局

桌面外框、导航、主题和圆角统一以 [桌面界面合同](DESKTOP_UI.md) 为准。不再使用手机抽屉或根据宽度切换模态。

- 导航和结果各自滚动，显式收起导航后释放正文宽度；同一棵导航 DOM 保留查询和选择。
- 问题框属于中央工作区，在数据／理解页隐藏但不卸载。已访问结果保留挂载，不因布局切换清除局部编辑。
- 只有显式动作交接焦点；结果与进展更新不抢焦点。真正的确认模态继续独占操作，普通桌面面板不是模态。
- 页面切换遵循 [React 合并相关状态](https://react.dev/learn/choosing-the-state-structure)：`ChatArea` 使用同一 reducer，面板可见性和数据页均从它派生。返回结果不调用全局 blur；导航焦点由工作台交接规则维护。五个定向用例及类型检查通过；Chrome 1180×700 中英文验证数据搜索、未发送问题与返回页签焦点保留，无写请求、页面错误或横向溢出。
- 空白页提供当前项目的问题入口。普通面板只呈现业务选择与结果，诊断留在明确打开的高级入口。

## 模块职责

| 模块 | 所有权 |
|---|---|
| AnalysisWorkbench | 当前结果、访问顺序、页面切换意图及布局组合 |
| workbench-pane | 结果／数据／项目理解的单一页面状态；结果页保留隐藏数据页的位置，不单独保存开关 |
| WorkbenchNavigation | 桌面导航的展开／收起、挂载保留与焦点返回 |
| InvestigationList | 当前已加载调查的分组、查找和较早记录展开 |
| ChatHeader / WorkspaceLinks | 当前项目动作与项目报表、项目切换、设置入口 |
| useResultReadingPosition / useWorkbenchPaneFocus | 会话内阅读位置与显式动作的焦点交接 |
| WorkbenchCommands | 复用 cmdk 的操作筛选与选择，不拥有业务执行 |
| ChatArea | 接入既有项目、提交、草稿、运行控制与数据工作区 |
| useStandingAnalyses / standing-attention | 按项目读取关注项、明确检查与续跑、互斥检查状态和业务原因翻译；页面不持有该流程的请求 |
| MessageList / MessageListStatus / useInvestigationTimeline | 时间线结果编排、待办及会话加载反馈、测量与阅读跟随分别维护；新进展从最新消息与阅读位置派生，不另用 effect 同步标记 |
| ChatEmptyState / AnalysisSuggestions / WorkspaceActivitySummary | 空白页组合提问、建议与项目活动；建议只交回问题，活动保留全部已加载关注项，检查中的条目禁止重复点击 |
| hasModalDialog | 区分常驻面板和真正模态；不以所有 open dialog 阻断快捷键 |

## 记录、阅读与搜索

- 当前记录最新优先；标题优先使用原始问题，确认答案不能替代调查标题。同项目／同 run 的多次消息分组，最新消息直接打开，较早记录默认折叠。没有 run 身份的消息独立显示，不按标题猜测归属。
- 消息 key 优先使用流身份，其次保存消息身份；获得 run 或保存身份不重建实时结果。旧数据确实没有身份时仍用顺序后备，不承诺任意插入重排。外部按 run 定位选择最新对应消息。
- 搜索对问题、报告标题和摘要做 NFKC、多词匹配；命中较早记录时保留组上下文，清空后恢复折叠选择。搜索不请求模型、不修改当前结果或访问顺序。
- 选择记录只切换当前会话内的结果。阅读旧结果期间新进展不会抢走页面；明确点击最新记录／最新结果才恢复跟随。通过前后导航返回最新结果仍保持固定阅读。
- 前后导航按访问顺序保留最近 50 个身份；后退后打开另一结果会替换前进分支。失效身份不可访问，连续更新同一结果不重复入栈，数据页和等待外部目标时不登记中间结果。它不是浏览器历史，也不是内容内存容量上限。
- 每条结果分别保留横纵滚动偏移。隐藏布局不覆盖已保存值；布局／图表尺寸晚到时尝试恢复，用户开始滚轮、指针或键盘阅读后停止自动等待，不维护单独手机触摸分支。作用域是本次项目／会话挂载，不是跨重启恢复或正文锚点。
- 仍可见的列表触发按钮保留焦点。“继续提问”只聚焦原草稿，不提交、不改变结果上下文。只有显式动作交接焦点，新结果／流式更新不抢焦点。
- 图形仅在真实绘图区宽高为正时挂载；隐藏时卸下图形，保留结果卡片、图表选择、精确值表和纠正草稿。重新显示会重新初始化 Recharts 内部动画／提示框，不承诺保留全部内部状态。

访问顺序参考 [VS Code history service](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/services/history/browser/historyService.ts)，分组采用普通 disclosure 按钮，不冒充完整 ARIA tree。

## 全部历史与项目

- 全部历史在窗口打开后才读取服务端摘要目录；默认每页 12 条、最多 50 条。问题／标题／摘要多词 AND 搜索覆盖项目，而非仅当前页；状态筛选、总数、页码收敛和页面选择由同一 SQL 语句快照产生。请求之间不是冻结快照。
- 目录不携带完整 report、checkpoint 或图表行。历史搜索投影由迁移 0030 和 ORM 写入维护；未来直接 SQL 修改问题或报告也须更新投影。项目归属来自分析运行，导航用途排除失效会话。
- 输入停顿 250ms、组合输入结束后查询。取消／旧响应不能覆盖新筛选；同筛选翻页可暂留上一页，同页刷新失败保留内容。换项目清空筛选；关闭再开同项目保留状态。搜索是子串扫描，不是全文索引或百万条容量承诺。
- 预览与明确打开分离。预览失败保留之前可读内容；运行中允许查找，但实际会话／项目切换和新建仍受原执行状态约束。工作台选择会通知上层当前结果，外部目标未到达时不误报旧结果。
- ProjectSwitcherDialog 集中项目搜索、新建与改名。目录按当前项目优先、元数据更新时间排序，先呈现 20 条并可展开；不是最近访问排序或服务器分页。
- 顶栏项目名打开项目目录，不再独立编辑名称。“数据”始终打开数据；待核对口径使用独立的项目理解入口，不随数量改变数据按钮的目的地。
- ChatArea 必须接收独立的项目入口，不回退到历史窗口。主页返回会话参数作为一次性请求消费；项目／会话不匹配时清除结果选择，不用 effect 在旧选择已渲染后重置。
- 创建和改名有同步锁，核对返回身份与名称后才更新元数据。失败或不明确的创建结果保留输入，允许刷新核对但不自动重复创建；等待期间上下文变化不会迟到切换用户。改名不清空来源、分析或会话。
- 历史、项目与快速操作之间明确交接，不叠加两套可操作模态。数据库与真实网络故障的保证以对应实现和专门检查为准，界面预览不证明它们。

## 问题输入

- composer-drafts 以项目和会话共同分隔文字草稿，新分析另有空会话草稿。原始空格、换行、中文和文字版本保留，不按名称合并、不静默淘汰。
- 当前标签页 sessionStorage 每次编辑写入并读回核对；失败时保留内存和重试入口。读取失败不能用空值覆盖旧记录；删除失败不能声称草稿已移除。公共离开保护覆盖未保留编辑，即使已离开工作台。
- 提交同步去重；接受回调必须对应提交时的项目、会话、流和未改变文字版本，不能清掉后续编辑。修改又改回同一文字也是新版本。submitWithAnalysisReceipt 核对调用后新建的流及其分析身份；没有启动新流时，旧回执不能证明本次成功。普通请求结束不是持久化回执。
- QuestionEditorDialog 编辑同一草稿，保留选区方向与相对滚动位置；不另建草稿、不提供提交按钮。项目／会话改变撤销展开状态，关闭返回普通输入。两个 textarea 不共享系统撤销栈。
- usePromptInsertion 统一处理建议、追问和待办编辑：内容不同且已有草稿时，由用户取消、追加或替换。按文字与版本比较，期间上下文或内容变化使旧选择失效。确认只填入，不调用模型；更换失败调查的服务不覆盖当前草稿。
- 草稿范围是当前标签页会话，不承诺关闭标签、重启应用、跨浏览器／设备或系统崩溃恢复。草稿仅含问题文字，不含文件选择或执行上下文。

输入交互参考 [Zulip 草稿](https://zulip.com/help/view-and-edit-your-message-drafts)与[展开输入](https://zulip.com/help/resize-the-compose-box)；没有引入独立编辑器或网络草稿服务。

## 建议、操作与运行

关注项检查由 `useStandingAnalyses` 统一维护，复用 [TanStack Mutation](https://tanstack.com/query/latest/docs/framework/react/guides/mutations) 的状态和完成回调，禁用自动重试与重连排队。目录 GET 接受取消信号；明确点击才调用 prepare-run。同步锁阻止重复检查，每次等待后重新核对项目会话及当前调查，离开再返回同项目也不续跑旧请求；已有新活动流时不覆盖它。正在检查从 mutation 状态派生，不永久写入反馈。准备请求可能已在后端生效，前端忽略迟到结果不代表撤销。

该模块 10 个定向与双语用例、限定 ESLint 和前端类型检查通过。Chrome 1180×700 中英文验证明确检查、等待禁用、无变化反馈与按钮恢复，无页面错误或横向溢出。准备响应被拦截模拟，没有真实续跑或模型调用。

- 建议接口最多提供三项，AnalysisSuggestions 使用固定桌面三列。生成／刷新由明确操作触发；刷新失败保留旧建议，成功空结果区别于失败。打开、重连或上下文改变不自动调用生成。
- useSuggestedQuestions 同步去重并取消过期前端请求。项目、模型、语言、来源版本／状态和已接受的项目理解刷新使旧建议失效；仅来源顺序变化不失效。前端取消不证明后端模型停止或不计费，刷新不保证建议不同。
- 建议请求复用 TanStack Mutation，明确 `retry: false` 与 `networkMode: "always"`；一次点击立即尝试，不保留断网重连后自动执行的请求。网络模式含义见 [TanStack 官方文档](https://tanstack.com/query/latest/docs/framework/react/guides/network-mode)。
- 快速操作直接复用已安装的 cmdk，提供八项已知业务入口；没有项目时隐藏项目报表，运行中禁止新建。搜索及移动选择不执行操作。
- ⌘⇧P／Ctrl+Shift+P 打开快速操作，⌘K／Ctrl+K 搜索当前记录；后者展开导航但不切走数据／理解页。真正模态拥有快捷键，桌面非模态导航不阻断操作。IME 和已处理事件不触发快捷键。
- 当前运行控制条在阅读旧结果或数据／理解页仍保留停止入口。按当前活动流匹配并在提交前重新核对，等待真实终态；成功先到不改写为已停止。控制消失时只恢复它原来持有的焦点。
- InvestigationActivity 展示完整问题、当前业务状态和可展开的最近动态。最多 12 条已知阶段，相邻等价阶段合并，不保存模型自由文本／参数／推理；节点表示收到过动态，不表示阶段已成功。
- 已收到结果但尚未收到流终态时显示整理／保存等待，不提前宣称报告已经保存。活动列表只属于当前前端会话，不是完整持久运行日志。
- 待办页仅保留原始问题、当前服务状态及继续／修改动作；收到问题不显示“已理解”或预造后续流程。加载与失败反馈不拥有请求，只有明确重试才交回调用方。

命令面板参考 [VS Code](https://code.visualstudio.com/docs/getstarted/userinterface#_command-palette)；运行呈现参考 [Streamlit status](https://docs.streamlit.io/develop/api-reference/status/st.status)，不预造固定流程、百分比或预计耗时。

## 业务确认

- BusinessConfirmation 使用原生单选，不预选、点选不提交；明确“确认并继续”才保存。提交、失败和回执使用互斥状态；等待锁定选择，失败保留并由用户重试。成功回执显示已确认，不等于调查已完成。
- 确认卡为桌面 12px 内容面板，选项和共享 Button 使用 6px 圆角，不使用手机全宽操作或装饰编号。等待时用 aria-disabled 保留提交按钮焦点，由同步锁拒绝重复提交；回执仅接管原来仍属于确认卡的焦点。
- 确认按项目、run 和具体问题隔离。store 共享确认锁，核对当前状态与返回的项目、会话、run、答案和可继续标志；按点击时的模型／连接／上下文续跑。期间上下文变化不自动续跑或停止另一调查。
- 同一 run 多个问题只更新最新对应问题的回执。恢复对话按消息顺序匹配问题和合法 business_confirmation 记录，拒绝错归属、无效选项、提前／重复回执；仅接受服务端已登记的键规范化，不根据相似答案猜测。
- 选项草稿只存在于已挂载问题中，不新增持久队列或后端幂等协议。缺少证据的历史记录不能冒充已确认。后端实际确认和续跑能力仍需真实链路验证。

交互参考 [GOV.UK Radios](https://design-system.service.gov.uk/components/radios/)，沿用当前组件与执行协议。

## 调查内容加入报表

- InvestigationPicker 使用同一分页历史目录的 report 用途：仅完成调查，可包含没有会话但仍保留结果的调查。按项目和来源身份定位，不用其他调查替代失效来源。
- 轻量 report-artifacts 目录只读身份、类型、标题和更新时间；明确展开／勾选才读取内容。单项按微秒更新时间核对，冲突不静默换值；它不是内容哈希或冻结事务。
- 同身份／版本合并读取，最多两项并发；关闭取消队列和在途请求。目录仍整体返回，一项明细仍整体下载，并发上限不是内存上限。
- 手动选择独立于当前调查、类型、搜索页和智能／手动模式；以项目、调查、内容类型和身份区分。已读选择固定本次值，重开调查不替换；可以移除再选新值。
- “选择全部新增”追加并跳过已有 artifact，不取消用户明确选择的重复项。预览表最多八行八列，加入保留完整精确值和来源；所有已选内容就绪后一次追加、一次撤销，不部分加入或自动保存。
- 跨调查按首次选择顺序加入，每条摘要在前，其余按选择顺序。移除后焦点落到相邻项或清单。关闭窗口取消本次选择，不扩展为跨重启草稿。
- 智能整理先产生当前调查的方案，明确应用后才读取新增内容并组装；不额外追加手动选择。方案可能本身包含相同内容，不能宣称自动消除所有重复。迟到／失败结果不能部分应用。

参考 [Metabase 的已保存问题组装](https://www.metabase.com/docs/latest/dashboards/introduction)与 [React Aria 独立选择状态](https://react-aria.adobe.com/selection)。报表保存／合并／恢复见报告编辑文档；筛选与图表联动统一见 [报表阅读层](REPORT_READING.md)。

## 预览与历史验证边界

在 apps/web 使用 Node 24 运行 `node scripts/preview-workbench.mjs`，打开输出的 127.0.0.1 地址。真实 Next.js 源码配合单独的 GET-only 虚构 API，使用 .next-workbench-preview 目录；非 GET 返回 405。不要把 localhost 与 127.0.0.1 混用导致的跨源错误改进生产客户端。

此前 27 个不同定向用例通过，限定 ESLint 与空白检查通过。覆盖主工作台选择／草稿／记录身份、抽屉焦点与响应式状态、搜索／快速操作模态边界、问题复用与项目顶栏。单元测试模拟 dialog 开闭，不作为原生焦点与布局证据。Chrome 使用原有虚构预览验证收起导航释放正文宽度、数据与结果往返、搜索、历史前后、Tab 双向循环和未发送草稿。修改 hook 参数期间出现一次热更新依赖数组警告；最终重新载入完成，无新增错误／警告。

未跑全量测试、生产构建、后端测试或桌面打包；没有真实上传、配置保存、模型调用或报表写入。原生 IME、完整读屏、长历史和大结果容量未由这些检查证明；手机已经退出产品范围。旧截图只代表其拍摄时版本，不作为当前全站改造完成证据。
